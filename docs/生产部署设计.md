# 生产部署设计

## 服务拆分

生产环境建议拆分为接口网关、Agent Worker、模型网关、语义检索服务、只读数据网关、任务存储与可观测平台。同步简单查询设置较短超时；复杂归因返回任务编号并由队列异步执行，避免长任务占满接口工作进程。

## 容量保护

- 网关按租户与用户限流，Redis Lua 脚本维护全实例共享令牌桶。
- 同步接口设置并发信号量，队列满时返回 429 和 `Retry-After`。
- 客户端采用指数退避并加入随机抖动，避免同时重试。
- 已接收的复杂任务持久化后返回任务编号，实例重启可从检查点恢复。
- 分别配置模型调用、SQL 执行和整个 Agent 的超时与预算。

## 状态恢复

检查点至少保存用户问题、身份与权限快照、指标版本、Schema 版本、当前计划、已完成步骤、SQL 哈希、证据编号、重试次数与 Trace 编号。恢复时重新验证凭据和权限，不能直接沿用已过期的授权结果。

## 发布策略

指标库、Schema 和提示词分别版本化。灰度发布时固定一部分租户到新版本，对比执行正确率、拒答率、端到端时延和单问题成本；出现安全拦截下降或关键黄金集回归时自动停止发布。
